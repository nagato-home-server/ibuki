# Daily 20260724

## Summary

イベント駆動型オープンネットワーク制御基盤の第1段階実装として、C版 Controller の骨格から Linux VM 上での namespace 検証まで進めた。

現時点では、YAML から Tunnel / Path / Intent を読み込み、Path Selection、Transition、Apply Plan 生成、strongSwan / VPP 向けコマンド生成、Linux namespace の Direct / Hub / Relay L3 smoke test まで確認できている。

## Implemented

- C版 Controller repository を追加した。
- `Intent`、`Path`、`Segment`、`Tunnel`、`Health`、`Transition`、`Error` の基本モデルを実装した。
- `explicit`、`priority`、`evaluated` の基本 Path Selection を実装した。
- `immediate`、`graceful` の Transition を実装した。
- `flow-preserve` は第2段階扱いとして明示的に未実装にした。
- Transition を `PREPARE`、`READY`、`COMMIT`、`CONFIRM` に分割した。
- rollback plan を生成するようにした。
- YAML loader を追加し、`tunnels`、`paths`、`intents` を読み込めるようにした。
- YAML validation を追加し、不明な tunnel/path 参照や重複 ID を検出するようにした。
- `swanctl.conf` 生成を追加した。
- `secrets` block と PSK 認証情報を生成するようにした。
- `swanctl --load-conns`、`swanctl --initiate`、`vppctl ip route add` の apply plan を生成するようにした。
- rollback 用に `vppctl ip route del`、`swanctl --terminate` を生成するようにした。
- Linux VM 用の scripts を追加した。
  - `vm-check.sh`
  - `vm-build.sh`
  - `vm-build-cc.sh`
  - `vm-generate-plan.sh`
  - `vm-netns-setup.sh`
  - `vm-netns-smoke.sh`
  - `vm-netns-clean.sh`
  - `vm-runtime-status.sh`
- `cmake` が無い環境でも `cc` だけでビルドできる fallback を追加した。
- Linux VM で namespace underlay を構成し、Direct / Hub / Relay の L3 経路 smoke test に成功した。
- namespace 内で site-a / site-b 用の direct IPsec 設定生成を追加した。
- namespace 内 charon 起動のための実験 scripts を追加した。

## Difficulties

- `cmake` が Linux VM に無く、最初の build が止まった。
  - 対応として `vm-build-cc.sh` を追加し、`cc` だけで build / test できるようにした。
- `swanctl` は入っていたが、`vppctl` / `vpp` は未導入だった。
  - VPP 実接続は後段に回し、まず strongSwan direct tunnel に集中する方針にした。
- `charon` は PATH に無かったが、`/usr/lib/ipsec/charon` に存在した。
  - `strongSwan discovery script` を追加して探索できるようにした。
- 独自 `STRONGSWAN_CONF` を使うと `abort initialization due to invalid configuration` で charon が起動しなかった。
  - 複数の config variant を probe した。
  - `minimal`、`vici_relative`、`vici_global`、`with_include`、`with_pid`、`abs_include`、`abs_with_pid` がすべて失敗した。
  - 一方で system default config では charon が起動することを確認した。
- `swanctl --uri ... --load-conns` の順序で失敗した。
  - Ubuntu 24.04 / strongSwan 5.9.13 では `--uri` が operation-specific option として扱われるため、`swanctl --load-conns --uri ...` に修正した。
- namespace ごとに charon を複数起動すると `/var/run/charon.pid` / `/var/run/charon.vici` が衝突した。
  - `/run` を namespace ごとに bind mount して分離する方式に変更した。
- スクリプトが `charon.pid` に wrapper process の pid を書いてしまい、charon 自身の pid file と衝突した。
  - wrapper pid は `eventnet-wrapper.pid` に分離した。
  - `charon.pid` は charon 自身に任せるようにした。
- socket file が存在しても daemon が生きているとは限らず、`Connection refused` が発生した。
  - socket existence だけでなく `swanctl --stats --uri ...` が通るまで待つようにした。
