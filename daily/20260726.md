## VPP Netns Host-Interface Preparation

追加 scripts:

- `vm-vpp-netns-setup.sh`
- `vm-vpp-netns-status.sh`
- `vm-vpp-netns-smoke.sh`
- `vm-vpp-netns-clean.sh`

構成:

- `site-a:vpp-client 172.16.1.2/30` <-> `VPP host-vpp-site-a 172.16.1.1/30`
- `site-b:vpp-client 172.16.2.2/30` <-> `VPP host-vpp-site-b 172.16.2.1/30`

- IPsec とは独立に、VPP が namespace 間の L3 forwarding plane として使えるか確認する。

次に VM で実行すること:

```sh

sudo sh scripts/vm-vpp-netns-status.sh
sudo sh scripts/vm-vpp-netns-smoke.sh
```

VM 実行結果:

- `vm-vpp-netns-setup.sh` が成功した。

- `vm-vpp-netns-smoke.sh` が成功した。
- `VPP netns smoke passed: site-a and site-b reached each other through VPP host interfaces.` を確認した。

これで、VPP が Linux namespace 間の L3 forwarding plane として使えることを確認した。

## Multi-step Scenario Harness

`eventnet_scenario` に `--step` を追加し、複数の条件変化を1コマンドで順番に検証できるようにした。

追加したstep:

- `direct-ok`
  - 通常時に priority selection で `path-direct` を選ぶ。
- `direct-failed`
  - active `path-direct` failureを注入し、`path-via-hub` fallbackを選ぶ。
- `direct-recovered`
  - hub active状態から priority selection に従って `path-direct` に戻る。
- `relay-best`
  - injected healthのloss/latency条件から evaluated selection で `path-via-relay-c` を選ぶ。

狙い:

- direct正常 -> direct障害 -> hub fallback -> direct回復 -> evaluated policy実験、という未踏デモ向けの流れを実networkなしで高速に再現する。

- `direct-ok` で `path-direct` が選ばれることを確認した。
- `direct-failed` で `path-via-hub` fallback が選ばれることを確認した。
- `direct-recovered` で `path-direct` に戻ることを確認した。
- `relay-best` で evaluated selection により `path-via-relay-c` が選ばれることを確認した。
