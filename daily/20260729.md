# Daily 20260729

## Security Audit

strongSwan / VPP / controller周辺で、不安な場所を横断的に確認した。

確認したこと:

- strongSwanの新しめCVEをNEWSとローカルcloneで確認した。
- VPPのsecurity advisoryと、CVE未付与だが安全修正に見えるcommit群を確認した。
- controller側のYAML入力、command生成、`system()` 実行、PSK生成、`swanctl.conf` 出力を確認した。
- 結果を `docs/security-audit-notes.md` に整理した。

見つけた主な不安:

- YAML由来値がshell commandへ直接入り、`system()` で実行される経路がある。
- `swanctl.conf` にPSKが平文で入り、demo scriptでは `chmod 644` されている。
- エラー時にsecret入りconfigを `cat` する箇所がある。
- YAML値がサイレントに切り詰められるため、ID衝突や意図しない参照が起き得る。
- 数値parseが `atoi()` / `atof()` で緩い。

難しかったこと:

- strongSwan / VPP本体のCVEと、現プロトタイプで実際に使っている機能面を分ける必要があった。
- OSS側は新しいcloneでは修正済みでも、VMで実行しているdistribution packageが同じとは限らないため、別々に扱う必要があった。

次に直すなら:

1. rootで動くruntime scriptのPSK権限・ログ漏えいを直す。
2. commandへ入るYAML値のallowlist validationを入れる。
3. `system()` を使う箇所を段階的に減らす。
4. VM package CVE check scriptを追加する。

## Shell Script Cleanup

公開前に `scripts/` を整理した。

やったこと:

- `scripts/vm-shell-check.sh` を追加し、全 `scripts/*.sh` を `sh -n` で確認できるようにした。
- `scripts/README-linux-vm.md` の冒頭に script map を追加した。
- README の quick start に shell構文確認を追加した。
- direct/hub IPsec config生成時、PSK未指定なら `/dev/urandom` からdemo用PSKを生成するようにした。
- `PSK=change-me` が指定された場合は拒否するようにした。
- secret入り `swanctl.conf` を `chmod 600` にした。
- `swanctl.conf` load失敗時にsecret入りconfig本文を表示しないようにした。

確認したこと:

- WSL経由で `sh scripts/vm-shell-check.sh` を実行し、全shell scriptの構文チェックが通った。
- 公開対象の文書・scriptから、ローカル絶対パスやユーザー名が残っていないことを確認した。

残っていること:

- `system()` 経路とYAML値のallowlist validationは未対応。
- IPsec/VPP runtime smoke はLinux VM側で再実行する必要がある。

## Shell Script Reduction

増えすぎた `scripts/` を少し減らした。

やったこと:

- `controller switch smoke`
- `controller fallback smoke`
- `controller recovery smoke`

上記3本を `scripts/vm-netns-controller-smoke.sh` に統合した。

新しい使い方:

```sh
sh scripts/vm-netns-controller-smoke.sh switch samples/linux-vm-netns.yaml
sh scripts/vm-netns-controller-smoke.sh fallback samples/linux-vm-netns.yaml
sh scripts/vm-netns-controller-smoke.sh recovery samples/linux-vm-netns.yaml
```

また、未参照だった `vm-strongswan-show-default-conf.sh` は削除した。

結果:

- `scripts/*.sh` は44本から41本になった。
- direct/hub IPsec や VPP の実行入口は、過去に実行実績があるため今回は残した。

追加で減らしたもの:

- `charon config probe script`
- `strongSwan discovery script`
- `network DNS check script`
- `VPP OS info script`

これらは、strongSwan設定探索、DNS不調、VPP apt source確認など、過去の停滞点を調べるための診断用だった。
現行のデモ手順では `vm-check.sh`、`vm-runtime-status.sh`、`vm-vpp-preflight.sh`、各IPsec/VPP smokeのログで十分なので削除した。

結果:

- `scripts/*.sh` は41本から37本になった。

## IPsec Script Consolidation

direct/hub IPsec の小さい補助scriptを `scripts/vm-netns-ipsec.sh` に統合した。

統合した操作:

- `direct generate/start/status/logs/smoke/stop/clean`
- `hub generate/start/status/logs/smoke/stop/clean`

新しい使い方:

```sh
sh scripts/vm-netns-ipsec.sh direct generate
sudo sh scripts/vm-netns-ipsec.sh direct start
sudo sh scripts/vm-netns-ipsec.sh direct status
sh scripts/vm-netns-ipsec.sh direct logs
sudo sh scripts/vm-netns-ipsec.sh direct smoke
sudo sh scripts/vm-netns-ipsec.sh direct stop

sudo sh scripts/vm-netns-ipsec.sh hub start
sudo sh scripts/vm-netns-ipsec.sh hub status
sh scripts/vm-netns-ipsec.sh hub logs
sudo sh scripts/vm-netns-ipsec.sh hub smoke
sudo sh scripts/vm-netns-ipsec.sh hub stop
```

削除したもの:

- direct/hub の `clean`
- direct/hub の `logs`
- direct/hub の `status`

`start` / `smoke` / `stop` / `generate` は中身が大きく、既に実行実績もあるので今回は残した。

結果:

- `scripts/*.sh` は37本から32本になった。
