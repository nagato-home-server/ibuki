## 今日の難しかった点・停滞

- WindowsビルドではUnixソケットAPIを直接使えないため、Linux実装とWindowsの明示的な未対応分岐を分けた。Windows側の回帰テストは通ったが、実ソケットsmokeはLinux VMで実施する必要がある。
- まだVICI APIへ直接接続しておらず、command adapterは`swanctl`／`vppctl`のdry-run境界に留まる。次はLinux VM上でソケット連携を確認し、その後VICI接続を設計する。
- 複数probeの実測smokeはLinux VMで未実施。現在はCLI入力とシミュレーションでの生成境界まで確認している。
- `--batch-size` は `EN_MAX_PATHS` を超えないよう入力検証を追加し、未完了batchをEOFで誤って適用しない仕様を文書化した。Linux側のtelemetry smokeにもDirect失敗・Relay失敗・Hub成功の3件をbatch 3で評価する回帰確認を追加した。
- VLAN route計画では、sub-interfaceを作成するだけでなく、明示routeの出力interfaceも `parent.VLAN` にするよう修正した。VPP edgeを持つ `samples/vpp-netns-routes.yaml` に `intent-vpp-vlan` を追加し、生成計画で `host-vpp-site-a.100` / `host-vpp-site-b.100` が使われることを確認した。純粋なroute例サンプルにはVPP edgeがなく、評価対象を取り違えたため一度検証に失敗した。
- VPP edgeを含む経路を `runtime_kind: vpp` として扱う分岐を追加した。これにより専用 `samples/vpp-vlan-netns.yaml` の生成器がunsupported終了にならず、`apply-selected.sh` / `apply-integrated.sh` もVPP-only planへ接続できる。Windowsで生成・終了コード0・VLAN interface routeを確認した。
- command adapterのshell境界を再監査し、既定のstrongSwan/VPP command rendererでtunnel ID、endpoint、traffic selector、route prefix、next-hop、interfaceへ許可文字検証を追加した。`;` などを含む値を拒否するテストを追加し、WindowsビルドとCテストが成功した。任意template commandは管理者が明示する拡張点として残るため、本番化ではshellを介さないexec/API adapterへ置き換える。
- 既定のstrongSwan/VPP command adapterをLinuxでは`fork`/`execvp`で実行し、shell template commandと分離した。VPP socket指定もexec経由になり、正常系のdry-run互換性を保ったままCMakeビルドとCテストが成功した。Windowsでは現行CLI互換のためsystem fallbackを維持している。
- `ibuki.event.path.v1` の `path_failed` / `path_recovered` をtelemetry parserで受け、既存health更新へ変換した。障害と健全Pathを同一JSONLスナップショットに入れるイベントsmokeを追加し、Hub fallbackとDirect recoveryを確認した。単独障害イベントでは他Pathがunknownになるため候補なしになることも確認し、smoke仕様へ反映した。
- イベントsmokeをUnix socket連続streamにも拡張した。同一接続から「Direct失敗＋Hub回復」「Direct回復＋Hub失敗」をbatch 2で送り、`eventnetd`が2回のreconcileを行う回帰をLinux VMで実行できる。socketは現時点では1接続で終了する最小実装であり、複数Agent接続は今後の差分として残る。
- telemetryの状態値を厳密化し、`healthy` / `degraded` / `failed` / `unhealthy` 以外を拒否するようにした。`degraded` と未知値のテストを追加し、既存のAgent JSONL互換性を維持したまま入力誤りを見逃さないようにした。
- `vm-evaluate.sh` に `event-reconcile` ケースを追加し、イベント入力のファイル版・Unix socket連続stream版を論文用評価summaryへ含めるようにした。通常のWindows Cテストは成功済みで、socket部分はLinux VMで実行する評価項目として切り分けた。
- `eventnetd --telemetry-socket` の起動安全性を改善した。`umask(0077)`でsocketを所有者限定にし、既存pathがsocket以外なら削除せずエラーにする。Linuxのlocal Agent境界でroot実行しても通常ファイルを誤削除しない。
- state file保存を一時ファイル＋renameへ変更し、reconcile成功後の状態が書き込み途中で破損しにくいようにした。Windowsでは既存ファイルを置換するために先に削除する互換分岐を使用する。
- VLAN評価で`runtime_kind: vpp`も必須確認に加え、VPP-only専用サンプルに対して誤ってHub waypointを要求していた条件を修正した。VLAN smokeの再実行時には既存のLinux VLAN linkを先に削除するようにした。
- VLAN smokeの`VLAN_ID=100`固定を撤廃した。入力値を1..4094で検証し、標準YAMLの`vlan_id: 100`だけを出力先の一時YAMLへ安全に数値置換してからController planを生成するため、複数VLAN条件を同じ経路で実験できる。
