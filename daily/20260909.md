## Telemetry JSON parserのyyjson移行

### 方針

TelemetryはAgent、strongSwan observer、VPP observerなど複数の外部プロセスから高頻度に入力されるため、手書きの文字列探索ではなく、速度とJSON仕様適合性を優先してyyjsonを採用した。JSONLの行単位処理とIbuki固有のschema・Identity・閾値検証は既存のController側に残し、JSON構文解析だけをライブラリへ分離する。

### 実装

- `third_party/yyjson/yyjson.c` と `yyjson.h` を同梱した。
- `src/telemetry.c` の文字列探索によるJSON解析をyyjsonのDOM解析へ変更した。
- Path Health、Path Event、Tunnel Event、VPP Route Event、VPP Interface Eventの既存schemaを維持した。
- RTT、Packet Loss、Jitter、連続成功／失敗回数、timestamp、VLAN/FIB関連の検証を維持した。
- `CMakeLists.txt`と`vm-build-cc.sh`の両方でyyjsonをリンクせずコンパイルできるようにした。

### 難しかったこと・停滞

- WSLが一時的に起動できず、Linux側の実ビルドをこの環境から再実行できなかった。
- Windows側のVisual Studio CMake検証はWindows SDKの権限エラーで停止した。
- そのため、yyjson移行後のLinux Cビルドと全テストは、WSL復旧後に必ず再実行する必要がある。
