# Daily 20260924

## 実施内容

- Archマシンの空き容量が限られ、VPPをローカルでビルド・導入しにくいため、Ubuntu 24.04のGitHub ActionsでFD.io VPPパッケージを使う手動namespace smokeを追加した。CIではIbukiの対象バイナリをビルドし、ローカルArchにはVPPを導入しない。
- `origin/main`の更新を取り込み、GRE namespaceサンプルと生成計画の整合を修正した。ローカルのCMake/CTest 27件はすべて成功した。
- IKE endpoint (`203.0.113.10`/`203.0.113.9`) とGRE outer endpoint (`198.18.1.1`/`198.18.2.1`) が異なる場合、strongSwan CHILD_SAをtransportではなくtunnel modeで生成するよう修正した。両siteで固定`/32[gre]` selectorのCHILD_SA確立を確認した。
- site namespaceにテストLANアドレス `10.10.1.1`/`10.10.2.1` を持つdummy interfaceを追加し、Linux転送、VPPのLAN戻り経路を構成した。
- Linux vethのMACとVPP AF_PACKET host-interfaceのMACが異なるため、Linuxの固定近隣表をVPPの実MACで設定するよう修正した。これでLAN pingパケットがVPPのIPv4入力へ到達した。
- 統合試験の失敗時にLinuxのアドレス・経路・近隣表・XFRMと、VPPのinterface・FIB・packet trace・errorを残すようにした。
- トポロジ初期化と生成計画がGREを二重作成していたため、統合試験では生成計画だけがGREを作成するようにした。
- 生成計画にはsite-a側GREしかなく、site-b側の経路追加がCLI parse errorになることが分かった。site-bのGRE作成、`10.255.0.2/30`設定、upを追加し、CMake回帰テストでも検査した。
- 現行構成を`docs/namespace-runtime-v2.md`に反映し、旧root VPP構成の制約資料には履歴であることを明記した。
